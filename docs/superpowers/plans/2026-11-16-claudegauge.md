# claudegauge Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Native macOS menu bar app that shows the Claude 5-hour session usage as a coloured battery-like gauge with the percentage inside, plus weekly usage, launch-at-login, log in and quit in its menu.

**Architecture:** Swift/AppKit app with no Dock icon. Pure-logic units (colour thresholds, reset text, credential decoding, header parsing, poller state machine) are unit-tested with XCTest; thin I/O shells (`/usr/bin/security`, URLSession, `Process`, `SMAppService`, `NSStatusItem`) wrap them. The Xcode project is generated by XcodeGen from `project.yml`, and the generated `.xcodeproj` is committed.

**Tech Stack:** Swift 6 toolchain (Swift 5 language mode), AppKit, ServiceManagement, XCTest, XcodeGen, macOS 14+.

**Spec:** `docs/superpowers/specs/2026-11-16-claudegauge-design.md`

## Global Constraints

- Deployment target macOS 14.0. Bundle id `io.github.rasrenan.claudegauge`. Product name `ClaudeGauge`, menu label "claudegauge".
- `LSUIElement = YES` (no Dock icon). App Sandbox OFF (the app runs `/usr/bin/security` and `claude`). Ad-hoc signing (`CODE_SIGN_IDENTITY = "-"`), hardened runtime OFF.
- No third-party Swift dependencies. XcodeGen is a dev-only tool (`brew install xcodegen`).
- Nothing copied from Clawdmeter (code, fonts, images). System font only.
- All user-visible text in English, exactly as written in the spec §3.4 / this plan.
- Colours: green `#788c5d` (<50), amber `#d97757` (50–79), red `#c0392b` (≥80), track `#2a2a28`.
- Poll interval 60 s; HTTP timeout 20 s; Keychain service `Claude Code-credentials`.
- Build/test commands always prefix `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer` (the active developer dir is Command Line Tools). Below, `XB` means:
  `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer xcodebuild -project ClaudeGauge.xcodeproj -scheme ClaudeGauge -destination 'platform=macOS'`
- Never `git push` or create a GitHub repo; commit locally only.
- **Deviation from spec §4 (recorded):** `TokenReader` reads the Keychain by running `/usr/bin/security find-generic-password -s "Claude Code-credentials" -w` instead of calling the Security framework directly. Reason: the "Always Allow" grant then belongs to Apple's signed `security` tool and survives every rebuild/reinstall of our ad-hoc-signed app (spec §2 side effect disappears); this is also the exact source of the hex-encoded output the spec asks us to decode.

## Review Focus

1. Garbage or out-of-range utilisation headers (`"abc"`, `1.37`, `-0.1`) → missing values are treated as absent, numbers clamped to 0…100; never crash. (Task 4)
2. Mac wakes from sleep with a stale gauge → a poll runs immediately on wake. (Task 5)
3. User denies the Keychain prompt or `security` exits non-zero → state is Not logged in, no crash, no retry storm (next try on the normal 60 s tick). (Task 3)
4. A reset date already in the past (stale reading) → "resets now", never a negative duration. (Task 2)
5. `claude auth login` hangs or is clicked twice → UI never blocks; a second click while one is running is ignored. (Task 7)

### Task 5: Usage poller (state machine)

**Files:**
- Create: `ClaudeGauge/UsagePoller.swift`, `ClaudeGaugeTests/UsagePollerTests.swift`

**Interfaces:**
- Consumes: `TokenStatus`, `TokenReader.status(now:)`, `FetchOutcome`, `UsageReading`, `UsageClient.fetch(token:)`
- Produces:
  - `enum GaugeState: Equatable { case starting; case ok(UsageReading, updated: Date); case notLoggedIn; case offline(last: UsageReading?, lastUpdate: Date?) }`
  - `@MainActor final class UsagePoller { init(readToken: @escaping () -> TokenStatus, fetch: @escaping (String) async -> FetchOutcome, now: @escaping () -> Date = Date.init); private(set) var state: GaugeState; var onChange: ((GaugeState) -> Void)?; func pollOnce() async; func start(); func stop() }`

- [ ] **Step 1: Failing tests** (fakes for both closures, fixed `now`):
  - initial `state == .starting`
  - token `.valid`, fetch `.reading(r)` → `.ok(r, updated: now)`; `onChange` called once with that state
  - token `.missing` → `.notLoggedIn`, fetch closure NOT called
  - token `.expired` → `.notLoggedIn`
  - fetch `.notLoggedIn` → `.notLoggedIn`
  - after `.ok(r, t0)`, fetch `.offline` → `.offline(last: r, lastUpdate: t0)`
  - from `.starting`, fetch `.offline` → `.offline(last: nil, lastUpdate: nil)`
  - from `.offline(last: r, ...)`, fetch `.reading(r2)` → `.ok(r2, ...)` (recovery)
  - unchanged state → `onChange` not called again
  - concurrent: calling `pollOnce()` twice before the first fetch returns performs only one fetch (in-flight guard)
- [ ] **Step 2:** `XB test -only-testing:ClaudeGaugeTests/UsagePollerTests` → FAIL.
- [ ] **Step 3:** Implement. `start()`: `Task { await pollOnce() }` immediately, a 60 s repeating `Timer` on main run loop, and an observer on `NSWorkspace.shared.notificationCenter` for `NSWorkspace.didWakeNotification` that triggers `pollOnce()` (Review Focus 2). `stop()` invalidates timer and removes observer. Token read runs off the main thread (`Task.detached`) because it spawns a process.
- [ ] **Step 4:** Same command → PASS. Add test `testWakeTriggersPoll`: post `NSWorkspace.didWakeNotification` on `NSWorkspace.shared.notificationCenter` after `start()` with a counting fake; expect fetch count to increase (use `XCTestExpectation`, timeout 2 s). Run → PASS.
- [ ] **Step 5:** Commit `"Add usage poller state machine"`.
